# Release 0.3.1 — Skill router pipeline

**Date:** 2026-11-27
**Tag:** `v0.3.1`
**Previous:** `v0.3.0` (trusted write loop)

## What is new

0.3.1 adds the deterministic skill router that turns a plan step into a small,
explainable skill queue:

```text
π (plan item) ──► cap[] from accept
σ (micro-step) ──► multi-marker consensus (≥3 signals)
τ (turn)      ──► fingerprint gate (re-emit only on change)
```

### Pipeline stages

| Stage | Module | What it does |
|---|---|---|
| Step registry | `mockup/step_registry.py` | Extracts σ from π, inherits `cap[]`, builds the current + 3-step window |
| Multi-marker | `mockup/skill_markers.py` | Category hint from ≥2 independent signal families (never a single verb) |
| Collection | `mockup/skill_index.py` | Reads 148 `SKILL.md` from `~/.config/opencode/skills`, `~/.claude/skills`; parses frontmatter + sections |
| BM25 | `mockup/skill_text.py` | Char 3–5-gram BM25 over 4 weighted fields (name ×2, tags ×1.5, description ×1, body ×0.3) |
| Consensus | `mockup/skill_consensus.py` | ≥3 signals → queue; 2 → advisory; ≤1 → gap. No single signal can force queue |
| Group select | `mockup/skill_group.py` | Two-level group → skill selection with learned weights and 1/10 exploration |
| Deep analysis | `mockup/skill_deep.py` | Produces `what/why/how`; `why` says “mentions”, never “provides” |
| Render | `mockup/skill_render.py` | Positional gradation, ≤800 chars, integers only, stable under identical fingerprint |
| τ-gate | `gates/tau_gate.js` | Fingerprint + idle-reissue counter. 5 µs per turn |
| Outcomes | `mockup/skill_outcomes.py` | Three tracks (read / call / accept) — never mixed |

### Data

- `mockup/skills.card.json` — 20 curated skill cards with verified `provides`.
- `mockup/capabilities.json` — 14 capabilities, 6 accept rules (unchanged from 0.3.0).

### New MCP tool

`dom_skill_select` (lite profile, read-only):

- input: `step` (title, context, cap, markers), optional `queue`, `plan_version`, `index_digest`
- output: `block` (≤800 chars) plus machine-readable `queue`, `advisory`, `gaps`,
  `prefetch`, `missing_caps`, `groups`, `confidence_bp`, `signals`.

## Invariants enforced

1. `mentions` never becomes `provides`; a missing provider is a visible gap.
2. No single signal can force queue mode (consensus ≥3).
3. Three outcome tracks never substitute for one another.
4. The selector is read-only with respect to the plan registry.
5. Injection block size depends on position, not confidence.
6. No floats in the injected block; integer basis points only.
7. τ-gate counts idle re-issues only; legit changes are not capped.

## Known limitations

- **Coverage:** 20 of ~150 skills have verified `provides`. The remaining ~130 are
  reported as uncurated, not silently covered. This is by design (R2).
- **`accept` on steps:** live plan steps do not yet have `accept` properties; the
  router is exercisable through the step input, but authoritative mode requires
  them. Adding `accept` is the next step (0.3.2 / 0.4.0).
- **No embeddings:** the dense channel is deferred. BM25 char-ngram is the
  reproducible baseline; embeddings remain an optional shadow channel.
- **`probe_mcp_plan_ingest.py`:** needs the optional `mcp` package; absent on this
  interpreter. Pre-existing, unrelated to 0.3.1.

## Upgrade

No schema migration. 0.3.1 is additive; the ledger remains at `user_version=5`
from 0.3.0. Both host trees (`opencode/`, `claude/`) are byte-identical for all
shared files.
