# DOM brief in `dom.notes` (2026-11-24)

## Why this exists

The previous index line only said `plan r16: N items, N open, N claims`. The owner requires the prompt to hold the **line**: root task → branch → sub-branch → current block, with each level's baseline, done/planned, risks, anchors, execution vector and checklists.

## Format

`plan_check_hook.py` now prints `mockup.brief.project_brief(svc)` when no check is due:

```text
[DOM MEMORY INDEX] plan r16 · 67 items / 54 open · 245 claims · CHAIN_OK
ROOT: Гони здесь (149d33e5)
LINE:
  П1 "…" [AA pending] baseline: … (claim 53677f9f)
CURRENT (auto): П1 "…" [AA pending] anchor 53677f9f
ACTIVE: not marked; set current_task on the root claim to pin the active block
DONE: 0 done in the current branch; PLANNED: П10, П11, П12, П13, П2, П3
RISKS: none linked
CONFLICTS: 0 open
RECENT MAIN: text 056d6851: …; quote 71a47ae7: …; decision e54e7f42: D-025 …
ANCHORS: root 149d33e5; plan r16; headers 53677f9f
VECTOR: read current anchor -> dom_task_claims -> claim/update with basis -> verify -> mark status
CHECKLIST:
  [ ] hold root/branch/current baselines before acting
  [ ] mark the active block with current_task when it changes
  [ ] no overwrite: dom_update creates a new version
  [ ] new claim: basis/refines/purpose and plan_task link
  [ ] branch is native: use the plan branch; variant only by fork/reconcile
  [ ] verify source/review/audit before accepting
  [ ] update the current block status after the work
```

- Baseline at each level is the header claim's `context` property, falling back to the title. It is a pointer; the full text stays in `dom_context`.
- `current_task` on the root request claim pins the active plan item (path, branch code or task id). Without it the brief selects the first `in_progress`, else the first open leaf, and says `CURRENT (auto)`.
- `RECENT MAIN` shows the latest main-branch claims not linked to a plan item. This is how 0.2.6 work remains visible while the plan still ends at r16.
- The brief is capped at 2,600 chars; long contexts are shortened with `…`.

## Holding the line across tool continuations

A brief queued on `prompt` is consumed by the first `context` call. A normal turn then makes many `context` calls for tool continuations; without a cache those would have `dom.notes=[]` again.

`opencode/index.js` now keeps `briefs: sessionID -> last prompt note`. When a `context` call has no queued note, it re-injects the cached brief. A new prompt replaces the cache. `tests/check_prompt_snapshot.mjs` calls the registered `context` handler twice and asserts `dom.notes.length >= 1` in both snapshots.
