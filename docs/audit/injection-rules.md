# Основные правила инжекции в промпт агента

**Дата:** 2026-11-28
**Основание:** анализ 146 снапшотов, root-cause analysis, live-тест dom-router
**Статус:** канон — обязателен к применению при разработке всех блоков DOM

---

## 0. Аксиома

**Каждый символ в промпте агента имеет цену.** 
- Средний промпт: ~80 332 chars (~20 083 токенов)
- Стоимость: ~$0.15/1M токенов → ~$0.003 за промпт
- 146 снапшотов = ~$0.44 только за инференс
- 96.7% промпта — не наш код. Наша цель: **каждый блок DOM должен быть <5% промпта и нести уникальную ценность.**

## 1. Инварианты инжекции

| # | Инвариант | Проверка | Отказ если |
|---|-----------|----------|------------|
| I1 | Каждый блок DOM в промпте решает ровно одну задачу | Блок имеет маркер: `dom.notes` — план, `dom.skill-queue` — скилы, `dom-help` — ошибки | Блок без маркера или с двумя задачами |
| I2 | Ни один блок DOM не дублирует функциональность host'а | Напр: skills — host грузит все 169, мы выбираем 3. Если permissions работают — дублирования нет | Один и тот же контент в host-блоке и DOM-блоке |
| I3 | Блок DOM ≤ 5% общего промпта | `len(block) / total_chars < 0.05` | Блок >5% |
| I4 | Промпт не содержит скилов, не выбранных роутером | `available_skills.count() <= queue.count() + 2` | >5 скилов в `available_skills` |
| I5 | Каждый блок имеет свою цель, измеримую метрику | В документации блока указана цель + как измерить | Нет цели или метрики |
| I6 | Отказ блока не ломает агента — fail-open | Блок может отсутствовать без ошибки | Агент падает при отсутствии блока |

## 2. Что и почему попадает в промпт

### 2.1. Что ДОЛЖНО быть (наше)

| Блок | Цель | Почему хорошо | Макс. размер |
|------|------|-------------|-------------|
| `dom.notes` | Дать агенту контекст плана и текущего шага | Без него агент не знает «где я» | 3 500 chars (сейчас 2 778) |
| `dom.skill-queue` | Дать агенту 3 лучших скила для шага | Без него агент выбирает из 169 случайно | 800 chars (сейчас 220) |
| `dom-help` | Подсказать действие при ошибке | Без него агент гадает, что делать | 200 chars (сейчас ~100) |

### 2.2. Что НЕ ДОЛЖНО быть (host-side)

| Блок | Почему плохо | Как убрать | Статус |
|------|-------------|-----------|--------|
| **Все 169 скилов** | Дублируют работу роутера (роутер уже выбрал 3) | `permissions: deny skill *` | ✅ −98.4% (71K→1.1K) |
| **Tool signatures (не-DOM)** | Агент их не использует (использует dom_help) | permissions для tools — не реализовано | ⏳ |
| **Code Mode catalog** | Нужен для execute(), но execute() не используется | Не убрать — платформа | ⏳ |

### 2.3. Что НЕ ДОЛЖНО быть (наше)

| Ситуация | Почему плохо | Как избежать |
|----------|-------------|-------------|
| Skill-queue без CAP | queue = `skill_search` — не релевантна | Не inject'ить queue при пустом cap; показать `gaps: not-declared` |
| dom.notes stale | План устарел, current_step неверный | Переингестить план перед инжекцией |
| dom-help при успехе | Сбивает агента | inject'ить только при ошибке |

## 3. Иерархия принятия решений

При разработке любого блока инжекции:

```text
План (глобальная задача)
  └── Почему этот блок нужен для глобальной задачи?
        └── Какой пункт плана он реализует?
              └── Какой шаг (σ) он обслуживает?
                    └── Какой скил для этого нужен?
                          └── Какой хук это inject'ит?
                                └── Что видит агент?
                                      └── Хорошо ли это для проекта?
                                            └── Есть ли альтернатива?
                                                  └── Почему эта альтернатива хуже?
```

**Для каждого компонента:**

```python
def evaluate_block(block):
    """Оценить блок по 5 критериям. PASS если все зелёные."""
    checks = {
        'purpose': block.has_clear_purpose(),        # I5
        'unique': not block.duplicates_host(),         # I2
        'size': block.chars() / total_chars < 0.05,   # I3
        'fail_open': block.can_be_absent(),            # I6
        'value': block.usefulness() > 0.5,            # субъективно
    }
    return all(checks.values()), checks
```

## 4. Критерии «хорошо» vs «плохо»

### Хорошо
- Блок inject'ится только когда нужен (τ-гейт экономит)
- Блок заменяет host-side контент (permissions)
- Блок ≤ 5% промпта
- Отказ блока не ломает агента (fail-open)
- Блок имеет явную цель и метрику

### Плохо
- Блок inject'ится всегда, даже когда не нужен
- Блок дублирует host-side контент
- Блок > 5% промпта
- Отказ блока ломает агента
- Блок inject'ится, но агент его не использует
- «Тихая смерть» — блок не inject'ится, никто не заметил
