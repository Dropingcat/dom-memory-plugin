# DOM Memory 0.2.6 — Observability

This release makes the agent loop inspectable.

## What is new

- **Prompt snapshot:** the OpenCode `context` hook writes `dom.prompt-snapshot/2` with `system`, `messages`, `tools`, `options` and `dom.notes`; the hash is computed before truncation; secrets are redacted.
- **Hook journal:** per-process JSONL with duration, session, extracted/injected sizes, snapshot id and `db_path`; retention and `dropped` counter.
- **Read-only monitor:** local web panel and JSON API for hooks, snapshots, DOM claims, plan and health. Bearer token, Host check, no CORS, no writes.
- **One memory resolver:** `DOM_DIRECTORY` wins; `OPENCODE_PROJECT_DIR` wins over an inherited `CLAUDE_PROJECT_DIR`; `db_path` realpath is reported by `dom_describe`.
- **Public projection:** `dom_describe` returns `directory` and `db_path`; `dom_plan_status` returns `inbox_queued`/`inbox_failed`.

## Assets

- `opencode-dom-memory-0.2.6.zip` — OpenCode plugin (flat tree; unzip anywhere and point `file:///…` at it).
- `dom-memory.plugin` — Claude Code plugin archive.

## Checks

The release suite is green in both trees (memory paths, preflight, inbox, statement capture, distillate pipeline/audit, monitor API/UI, hook journal, prompt snapshot, MCP plan-ingest probe). Live MCP verified after restart: `DESCRIBED`, `PLAN_STATUS`, `CHAIN_OK`, 13 hook events and 13 snapshots.

## Known limitations

- This is observability only. No `WriteContext`, no `read_receipts`, no write gate; those are 0.3.0.
- The snapshot is DOM-position pre-lowering, not the provider's raw HTTP body; a plugin registered after DOM is not captured (`hook_order: unknown`).
- The native OpenCode side panel is 0.3.1; the web panel is the 0.2.6 deliverable.
- `memory_runtime_snapshot.json` is generated and machine-specific; not a portable artifact.
